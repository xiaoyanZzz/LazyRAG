# 法律依据检索与时效核验

本文件是核验流程，不是法律依据库。文件中的问题清单只能用于发现核验事项，不能被引用为现行法结论，也不能使任何规则自动获得“已核验”状态。

## 目录

1. 核验原则
2. 官方来源顺序
3. 检索流程
4. 时效陷阱检查
5. 输出规范

## 1. 核验原则

法律和监管信息具有时效性。凡需要精确法律名称、条号、原文、生效日期、地方口径或案例时，必须在当前任务中核验，不依赖模型记忆或来源 Skill 中的静态内容。

只有本次任务中成功打开官方正文，并核对公布机关、效力状态、施行日期和相关条文，才能标记“已核验”。搜索结果页、摘要、本文件、其他 reference、模型记忆、商业数据库或二手文章都不满足该条件。

用户禁止检索、工具不可用或官方正文未成功打开时，进入“离线或未核验模式”。此时只做合同文字和商业风险分析；成品不列候选法律名称、条号、法条引文、生效日期、执法机关、罚款或确定性效力结论，法律状态固定写 `待核验（本次未打开官方正文）`。

区分：

- **法律规则**：来自现行法律、行政法规、司法解释和有权机关文件。
- **裁判参考**：来自指导性案例、典型案例或公开裁判，不等同普遍规则。
- **商业建议**：基于风险分配和交易经验，不得包装成法定义务。
- **待核验事项**：来源不可访问、法域不明、地方差异或新旧法衔接尚未确认。

## 2. 官方来源顺序

优先级从高到低：

1. 国家法律法规数据库：`https://flk.npc.gov.cn/`
2. 中国人大网：`https://www.npc.gov.cn/`
3. 最高人民法院及最高人民法院公报：`https://www.court.gov.cn/`、`https://gongbao.court.gov.cn/`
4. 中国政府网、国务院公报和国务院部门官网
5. 司法部、市场监管总局、国家税务总局、网信办、人社部等主管机关官网
6. 省级人大、政府、法院和主管机关官网，用于地方规则

商业数据库、律所文章和新闻可以帮助定位问题，但不能替代现行官方原文。搜索摘要不能作为最终证据；应打开并核对正文、公布机关、文号、发布日期、施行日期和效力状态。

## 3. 检索流程

1. 明确法域、合同类型、行为时间、履行地和争议阶段。
2. 把业务问题转换为法律要素，例如“违约金能否调减”拆为损失基础、举证、衡量因素和调减请求。
3. 先检索法律名称，再在官方正文内定位关键词和条号。
4. 同时检查配套司法解释、实施条例、修订决定和时间效力规定。
5. 检查是否存在特别法、地方规则、行业监管或当事人身份例外。
6. 把检索结果与合同事实逐一对应；不相关的法条不堆砌。
7. 记录访问日期和来源链接。无法核验原文时，不输出带引号的“法条原文”。

## 4. 时效陷阱检查

以下清单只提示“需要查什么”，不提供现行结论、条号或生效日期：

- 一般合同规则：核对是否存在特别合同规则、司法解释和时间效力问题。
- 违约金：核对调整请求、参照基础、举证责任和综合衡量因素，不把相对合同金额的固定比例当作安全线。
- 股权转让：按交易发生时间核对当时有效的公司法文本、内部程序、优先购买安排及未届出资期限股权的责任。
- 税费与发票：按交易发生时间、纳税人身份和交易类型核对现行税法及配套规则。
- 仲裁协议：按订约和争议发生时间核对现行仲裁法及司法解释，不沿用记忆中的旧条号或旧构成要件。
- 数据、网络安全、竞争、劳动用工及行业监管：核对特别法、地方规则、主体身份和最新修订。

## 5. 输出规范

已核验法律依据按以下格式记录：

```text
《法律或司法解释全称》第X条（效力状态；施行日期）
规则要点：仅概括与当前问题直接相关的内容
适用分析：说明事实如何满足或不满足适用条件
来源：官方链接（访问日期：YYYY-MM-DD）
```

用户明确要求原文时，只引用已打开核验的必要片段；不同来源文本有差异时优先国家法律法规数据库或公布机关版本并说明差异。无法确认条号时写“依据《某法》关于某事项的现行规定，具体条号待核验”，不要猜测。

未达到核验条件时，不设置候选依据或法律规则栏目，改用：

```text
法律状态：待核验（本次未打开官方正文）
当前分析性质：合同文字与商业风险分析
待办：如需法律依据，另行打开并核对官方正文
```

内部 reference 不得出现在“来源”字段，也不得表述为“依据本 Skill 已完成核验”。
