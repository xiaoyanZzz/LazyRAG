# 合同法务交付格式

## 1. 合同初稿

默认顺序：

1. 文件状态：草稿、适用法域、用户立场和版本日期
2. 待确认事项清单
3. 合同正文
4. 附件清单和需要补充的附件内容
5. 起草说明：关键设计、默认假设、谈判点和已核验依据

合同正文保持正式、克制，不使用 emoji，不把内部风险说明混入可签署正文。`【待确认】` 和 `【待协商】` 用于尚未得到授权的事实或数字；不得用占位符掩盖核心交易尚未形成合意。存在任何占位符时，文件状态必须标记“谈判草案，不可直接签署”。

## 2. 合同审查报告

```markdown
# 合同审查报告

## 审查范围
- 文件与版本：
- 用户立场：
- 法域与截止日期：
- 未读取或无法确认的材料：

## 结论
- 整体风险：重大 / 重要 / 可接受 / 信息不足
- 红色、黄色、绿色、灰色事项统计：
- 前三项关键问题：

## 风险详表
| 等级 | 位置 | 问题与触发场景 | 影响 | 依据状态 | 首选修改 | 谈判底线 |
|---|---|---|---|---|---|---|

## 缺失条款与附件

## 联动风险

## 谈判顺序
- 必须争取：
- 重点争取：
- 可以交换：

## 下一步动作
```

风险较多时完整列出所有红色和灰色阻断项，其余可先汇总，但应提供展开入口，不得静默丢弃。

## 3. 法务审批意见

```markdown
# 法务审批意见

- 合同与版本：
- 交易目的、金额与期限：
- 申请审批事项：
- 我方角色：

## 审批结论
同意 / 附条件同意 / 退回修改 / 升级专项复核

## 阻断项或放行条件
| 条件/问题 | 责任人 | 完成时点 | 所需证明 | 未完成后果 |
|---|---|---|---|---|

## 已接受的剩余风险

## 履约控制与复核节点

## 说明
本意见是辅助法务分析，未在任何 OA、用印或签署系统中执行审批。
```

## 4. 版本对比报告

先写基准版和对比版，再给变更统计、重大变化、组合风险、数字变化和谈判建议。重大项需同时提供两版原文和反提案；纯格式差异放在附录汇总。

## 5. 法律问题备忘录

采用“结论 → 可执行建议 → 事实与假设 → 分析 → 已核验法律依据或候选依据（待核验） → 不确定性与下一步”。精确法条必须来自本次任务成功打开的官方正文，并包含官方来源和访问日期；商业建议与法律规则分开。内部 reference 不能作为法律来源。

## 6. 文件与发布

- 默认直接交付 Markdown。
- 用户要求下载时，优先使用 `save_chat_artifact` 保存 `.md`；结构化审查结果可另存 `.json`。
- 用户明确要求飞书文档且工具可用时，使用写作或云文档能力发布，发布后返回真实链接。
- 宿主没有可靠 DOCX 生成器时，不承诺 Word。可以提供适合粘贴到 Word 的完整文本与排版说明。
- 若宿主以后提供 DOCX 工具，建议使用 A4、清晰标题层级、连续编号、页码、独立签章页、附件分页，以及醒目的待确认标记；格式条款是否需要特别提示应结合现行法律和具体订约过程判断，不能只靠加粗自动满足法定义务。

交付链接必须来自真实工具结果，不构造路径、预览页或有效期。
