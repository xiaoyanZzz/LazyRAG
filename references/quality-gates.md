# 合同法务质量门

交付前逐项检查。任何阻断项未解决时，降低结论强度或给出“退回修改/信息不足”，不得为了完成任务强行放行。

## 0. 安全硬门

以下任一项不通过时，禁止提交原答案，必须先删除、降级或改写：

- [ ] 离线或未核验任务已在所有其他模块之后最后读取 `references/offline-safety.md`，读取后没有再加载其他 reference
- [ ] 凡标记“已核验”的法律内容，均有本次任务成功打开的官方正文、链接和访问日期；Skill、reference、搜索摘要和模型记忆未被当作核验来源
- [ ] 离线或未核验模式下，法律状态逐项固定为 `待核验（本次未打开官方正文）`，没有具体法律名称、条号、法条引文、生效日期、执法机关、罚款、“已核验”或确定性效力结论
- [ ] 每个金额、比例、期限、日期、SLA 和责任上限均能追溯到用户输入、合同原文、确定性计算、本次已核验官方规则或明确标记的演示数据
- [ ] 不在数字来源白名单内的数值均已替换为 `【待协商：…】` 或 `【待确认：…】`，没有用行业惯例补数
- [ ] 存在未缓释红色或影响签署安全的关键灰色事项时，结论只能是“退回修改”或“升级专项复核”
- [ ] 仅审查部分条款或附件不全时，结论明确限定为局部审查，没有表示整份合同可以签署

### 离线成品逐字扫描

- [ ] 已先建立用户输入和合同原文的数字许可表；除用户明确要求的确定性计算外，成品没有许可表之外的阿拉伯数字、中文数字加单位、百分比、金额、日期或期限
- [ ] 触发场景没有虚构停机时长、数据量、损失金额、罚款、整改期限或行业阈值
- [ ] 替换条款和谈判底线中的未知数均使用 `【待协商：…】` 或 `【待确认：…】`
- [ ] 占位符中没有候选数字、X、Y、“例如”或推荐值；替换条款优先复用 `offline-safety.md` 的安全条款骨架
- [ ] 成品使用条款主题而非序号，没有统计条款数、风险数或待确认事项数；每个条款块都单独重复固定法律状态
- [ ] 工具调用后的响应直接从成品开始，没有“正在读取”“已完成读取”“接下来分析”或“现在开始输出”等过程播报
- [ ] 没有“行业惯例”“通常为”“最低不得低于”等未经来源支持的取值表达
- [ ] 没有“候选依据”栏目；离线法律状态后没有追加模型记忆中的法律名称或规则摘要

## 1. 输入完整性

- [ ] 文件名、版本、附件和签章页已确认
- [ ] 用户立场、合同类型、法域和交易目的已确认或显式假设
- [ ] OCR 模糊、文本截断、缺页和引用附件缺失已标注
- [ ] 关键金额、期限、币种、税费和比例来源可追溯

## 2. 起草完整性

- [ ] 主体、标的、对价、履行、责任、退出和争议安排齐全
- [ ] 类型专属条款已按 `contract-types.md` 检查
- [ ] 每项核心义务包含触发、标准、证据、后果和救济
- [ ] 所有重大默认值均以待确认形式出现，没有静默代入
- [ ] 定义、正文、附件和优先顺序一致

## 3. 审查完整性

- [ ] 不仅审查现有条款，也检查缺失条款和缺失附件
- [ ] 每个红黄灰问题都有位置、场景、影响和可执行建议
- [ ] 已检查付款验收、责任上限、IP 保密、数据退出等联动
- [ ] 风险评级基于影响和可能性，不由固定比例或数量机械决定
- [ ] 绿色事项没有被表述成“绝对安全”

## 4. 法律准确性

- [ ] 精确法律名称、条号、原文和生效日期来自已核验官方来源
- [ ] 已检查新旧法、时间效力、特别法和地方规则
- [ ] 没有把经验区间、行业惯例或案例观点写成强制法律规则
- [ ] 没有沿用模型记忆、来源 Skill 或其他静态资料中的旧条号和旧生效日期
- [ ] 无法核验的依据已标注，不存在编造原文或案例

## 5. 数字与逻辑一致性

- [ ] 总价、分期金额或比例、税额和大写金额一致
- [ ] 日期顺序、工作日/自然日、续约和通知窗口一致
- [ ] 交付、验收、付款、质保和解除触发没有循环或断点
- [ ] 违约金、赔偿、责任上限和例外之间不冲突
- [ ] 仲裁与诉讼没有作为并列终局争议方案

## 6. 审批与升级

- [ ] 审批结论属于四种标准结论之一且理由充分
- [ ] 附条件同意列明责任人、时点、证明和未完成后果
- [ ] 红色或影响签署安全的关键灰色事项没有被未授权地接受，也没有给出“同意”或“附条件同意”
- [ ] 涉外、控制权、担保、反垄断、数据跨境、国资金融或重大劳动事项已升级专项复核
- [ ] 没有声称已完成 OA、用印、签署或有权审批

### 电子签转交

- [ ] 只有用户明确要求电子签，并在看到准确文件名与版本后再次确认，才向腾讯电子签上传文件
- [ ] 上传对象是完整、可定位且不含 `【待确认】`、`【待协商】` 或未缓释红色/关键灰色风险的 PDF
- [ ] 用户已确认其有权处理合同及其中的个人信息、商业秘密，并同意把文件发送给腾讯电子签
- [ ] 用户在聊天中提供的 Token 只作为不透明字符串传给 `--token`，没有被改写、复述或保存；否则使用部署方的 `ESIGN_TOKEN`
- [ ] 只调用 `scripts/tencent_esign.py` 的 `auth-check`、`upload`、`prepare` 和 `handoff` 白名单命令
- [ ] 结果只表述为“已生成发起链接”；没有声称合同已发起、已用印、已签署或具有最终法律效力

## 7. 交付质量

- [ ] 结论在前，事实、风险、建议和依据结构清楚
- [ ] 替代条款可以直接使用，谈判建议包含备选和底线
- [ ] 合同正文不含内部说明、营销内容或无关 emoji
- [ ] 只返回真实生成的文件或文档链接
- [ ] 明确说明能力边界，但不以免责声明代替实质分析
