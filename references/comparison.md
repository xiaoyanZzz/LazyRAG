# 合同版本语义对比

## 1. 固定比较基准

明确基准版、对比版、文件名、版本号和日期。用户未指定时按上传顺序暂定并在报告开头声明，不把猜测隐藏在结果中。

检查两个版本是否完整，尤其是附件、表格、脚注、修订痕迹和签章页。OCR 或分页差异可能造成伪变更时单独标注。

## 2. 按功能对齐条款

先按主体、定义、标的、价格、履行验收、知识产权、数据保密、责任、期限退出、担保、争议和附件分类，再进行语义匹配。不要依赖条款编号或位置，因为重新编号、拆分和合并不等于实质变更。

把变化分类为：

- 新增
- 删除
- 实质修改
- 位置或结构调整
- 仅文字或格式变化
- 无法可靠对齐

识别“可以/应当”“或/且”“包括/仅限”“合理/唯一判断”“知悉/应当知悉”等细小但改变义务强度的词。

## 3. 评估实质影响

从以下角度判断：

| 角度 | 需要回答的问题 |
|---|---|
| 权利义务 | 谁新增权利、加重义务或丧失控制力 |
| 经济 | 价款、成本、现金流、赔偿敞口和税费如何变化 |
| 时间 | 期限、通知、验收、整改、续约和退出窗口如何变化 |
| 证据 | 举证责任、证明文件和默示规则是否改变 |
| 可逆性 | 风险发生后能否通过整改、解除、替代履行或保险恢复 |
| 合规 | 是否引入新的审批、许可、竞争、数据或劳动风险 |

数字变化同时列出旧值、新值、绝对变化和百分比；分母为零或单位不同不得强行计算百分比。日期变化同时评估工作日、自然日、节假日和前置条件。

## 4. 检查组合风险

调用 `review-and-approval.md` 的联动清单。特别检查“付款提前 + 验收变严”“责任上限降低 + 上限例外删除”“自动续约 + 不续约通知提前”“IP 归属变化 + 保密放宽”等组合。

## 5. 形成报告

先给变更全景和总体倾向，再按重大、重要、轻微排序。每个重大或重要变化包含：两版位置、必要原文、变化性质、对我方影响、法律状态、接受/拒绝/协商建议、反提案文本。

对方修改动机只能作为“谈判假设”，并列出支持证据和替代解释，不写成确定事实。纯格式差异汇总即可，但不得遗漏看似格式变化、实际改变文本内容的情况。

交付末尾给出必须争取、重点争取和可交换事项；如用户要求，基于对比版继续执行全面审查或生成我方反提案清洁版。
