## 1. 起草输入模型

先形成一页交易任务书，不直接从标题开始写正文。

| 模块 | 需要确认的内容 | 缺失时处理 |
|---|---|---|
| 主体 | 法定名称、主体类型、角色、授权与关联关系 | 使用角色占位，不推断真实名称或授权 |
| 交易 | 标的、范围、数量、地域、排除项、依赖条件 | 将范围边界列成附件或清单 |
| 对价 | 金额、币种、含税口径、计价方式、调价机制 | 只给计算结构，不填实际价格 |
| 履行 | 里程碑、交付、验收、付款触发、发票、质保 | 用 `【待确认】` 标记关键日期和标准 |
| 权利 | 所有权、知识产权、数据、成果使用、排他安排 | 同时区分既有权利与新增成果 |
| 风险 | 违约、赔偿、责任上限、保险、担保、不可抗力 | 先识别风险承担方，再写责任条款 |
| 退出 | 期限、续约、解除、过渡、返还、删除和结算 | 写清退出后的存续义务 |
| 争议 | 适用法律、协商、仲裁或诉讼、履行地 | 仲裁和诉讼不得作为并列终局方案 |

确认用户立场：保护甲方、保护乙方或平衡型。保护某一方不等于无限扩大其权利；仍需确保条款合法、可解释且能够被对方接受和执行。

## 2. 结构设计

按交易复杂度选择结构，通常包含：

1. 标题、编号、当事人信息和鉴于条款
2. 定义、解释规则和文件优先顺序
3. 标的、服务范围、排除项和附件
4. 价格、税费、发票、支付条件和抵扣规则
5. 交付、风险转移、验收、异议和整改
6. 双方义务、配合事项、人员与分包
7. 陈述保证、持续承诺和合规义务
8. 所有权、背景知识产权、成果知识产权和许可
9. 数据处理、信息安全、保密和披露例外
10. 质保、维护、服务等级和业务连续性
11. 违约、赔偿、责任限制、第三方索赔和保险
12. 期限、续约、暂停、解除和退出协助
13. 不可抗力、情势变化、变更控制和通知
14. 争议解决、适用法律、送达和证据约定
15. 完整协议、可分割性、弃权、转让和附件效力
16. 签章页与附件清单

短合同可以合并章节，但不得因追求简短省略核心交易条件和退出机制。

## 3. 条款工程方法

### 3.1 使用“条件—义务—标准—证据—后果—救济”模型

每项关键条款依次回答：

- 什么事件触发义务？
- 谁在什么时间、地点、以何种方式履行？
- 怎样才算完成或合格？
- 用什么记录、单据或系统日志证明？
- 未履行或不合格产生什么后果？
- 守约方可以要求整改、替代履行、扣款、解除还是赔偿？

避免“及时、合理、适当、尽快、重大”等无判断标准的词。无法完全量化时，至少给出判断主体、程序、证据和异议期限。

### 3.2 让付款与交付验收闭环

逐笔对应金额或比例、到期条件、所需单据、发票要求、审核期限和争议金额处理。区分签收、初验、终验和默示验收；不得仅写“验收后付款”而不定义验收。

### 3.3 让责任与可预见风险匹配

先列可能损失，再设计违约金、实际损失赔偿、责任上限、上限例外和减损义务。不要把固定比例描述成法院一定支持的安全值。责任上限应说明计算基数、适用期间、是否累计，以及欺诈、故意、重大过失、保密、知识产权、数据安全和人身损害是否例外。

### 3.4 预置证据

约定有效通知地址、授权联系人、电子邮件或系统记录的证明作用；列明交付清单、验收报告、变更单、工时或服务报告、会议纪要和发票等证据。证据条款不得不合理排除法定证据或剥夺一方救济。

### 3.5 控制定义与文件冲突

对服务、成果、工作日、安全事件、重大违约、关联方等关键术语只定义一次。列明正文、补充协议、订单、技术附件、报价和招投标材料的效力顺序；新文件优先只适用于明确修改的事项。

## 4. 缺失信息处理

把缺项分成三类：

- **必须先确认**：主体和角色、标的、价格或计价逻辑、核心期限，以及会造成重大单方风险的责任上限、排他、担保、知识产权或争议方案。
- **可以带标记起草**：具体地址、联系人、账户、发票信息、附件编号和非核心操作时限。
- **可以建议但不得静默采用**：付款比例、验收天数、质保期、服务等级、违约金和通知期。写成 `【建议值—待确认：依据与取值】`。

### 4.1 数字来源与占位符

起草前逐项标记数字来源。只允许使用用户输入、合同原文、基于已提供数字的确定性计算、本次已核验官方规则，或用户明确要求且标注“示例，不得直接签署”的演示数字。

用户没有授权具体取值时，不提供推荐数值，直接写明参数和取值依据，例如：

- `服务可用性不低于【待协商：SLA 指标及统计口径】。`
- `乙方应在【待协商：整改期限】内完成整改。`
- `累计责任上限为【待协商：计算基数、适用期间及金额或比例】。`

含上述占位符的文本是可继续谈判的草案，不可直接签署。不得用“行业惯例”“通常为”或“建议值”替换占位符。

用户要求“示例模板”时可以填入演示数据，但要在标题和关键字段中注明“示例，不得直接签署”。

## 5. 修订与谈判版本

根据审查结果修订时：

1. 固定原合同版本和用户立场。
2. 只修改授权范围内的条款，避免无声改变其他权利义务。
3. 同时提供首选文本、可接受备选和不可接受底线。
4. 检查修改对定义、付款、验收、责任、解除和附件的连锁影响。
5. 交付清洁版时另附变更摘要；需要谈判时按“必须争取、重点争取、可交换”排序。
